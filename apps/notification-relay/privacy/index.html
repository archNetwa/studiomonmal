1. 적용 대상과 개발자

본 방침은 Studio Monmal이 개발·배포하는 Android 앱 알림전달자(Notification Relay)에 적용됩니다. 앱은 사용자의 설정에 따라 SMS/MMS와 선택 앱 알림을 Telegram 또는 Discord로 전달합니다. 앱 자체 회원가입·계정 시스템과 Studio Monmal 사용자 데이터 서버는 없습니다. 개인정보 문의: studiomonmal@gmail.com.

2. SMS와 MMS 접근·사용

SMS 전달을 위해 발신자, 메시지 본문, 수신 시각, 확인 가능한 수신 번호/SIM 관련 정보를 처리할 수 있습니다. 신규 SMS는 Android broadcast로 처리하며, 일부 누락·정체 SMS의 재구성·복구를 위해 Android SMS provider에서 메시지를 재조회할 수 있습니다.

MMS 전달을 위해 발신자, 텍스트, 이미지, MIME/첨부 metadata와 수신 정보를 처리할 수 있습니다. 본문·이미지를 읽기 위해 Android Telephony provider를 사용합니다. 누락·정체 확인을 위한 provider consistency audit는 최근 provider 데이터를 조회할 수 있으므로 신규 broadcast에만 접근하는 것은 아닙니다. 복구는 제한적이며 모든 누락의 복구를 보장하지 않습니다.

3. 알림 접근과 필터

시스템이 전달하는 package와 알림 상태 등 최소 metadata로 조기 제외 조건과 앱 선택 여부를 확인합니다. 전달 대상으로 선택한 앱에 대해서만 relay 처리용 package/application identity, 앱 이름, title, text/bigText, subText와 처리 시각을 사용합니다. 선택되지 않은 앱의 알림 본문은 relay용으로 추출하지 않습니다. 알림 이미지와 첨부파일은 전달하지 않습니다.

사용자가 설정한 SMS/MMS 발신자 규칙, 메시지 본문 키워드, 알림 include/exclude 조건과 선택 application package로 전달 여부를 판단합니다. 알림 exclude 조건이 include 조건보다 우선합니다.

4. 기기 밖 전송과 제3자 서비스

필터 등을 통과한 데이터는 사용자가 직접 설정한 Telegram Bot API 또는 Discord webhook으로 HTTPS를 통해 전송됩니다. 전달 정책에 따라 한쪽 또는 양쪽으로 보내거나 Telegram 영구 실패 후 Discord를 사용할 수 있습니다. 일반 relay는 Studio Monmal 소유 중계 서버를 거치지 않으며, Studio Monmal이 메시지 내용을 자체 서버에 업로드·보관하는 구조가 아닙니다.

전달되는 메시지·이미지와 관련 metadata는 기기 밖으로 나갑니다. 전송 이후 Telegram/Discord에서의 처리·보존과 다른 이용자의 접근은 해당 서비스 정책과 사용자의 계정·채팅/채널·공유 설정에 영향을 받습니다. 사용자는 전달 대상에 해당 데이터를 보낼 권한과 설정을 확인해야 합니다.

5. 연결정보와 로컬 저장

사용자가 입력한 Telegram bot token, Telegram chat ID, Discord webhook URL과 설정은 기기의 앱 전용 private storage에 저장됩니다. 앱 자체의 추가 credential 암호화 계층은 현재 구현되어 있지 않습니다. 설정 저장소는 Android cloud backup 및 device transfer 대상에서 제외되어 있습니다.

신뢰성 있는 백그라운드 전달, retry, deduplication과 recovery를 위해 SMS sender/body의 pending WorkManager input, notification pending payload, 전달 진행 metadata, 필터 이력과 health/recovery metadata 등의 일부 데이터가 로컬에 저장될 수 있습니다. 이력·진단에는 메시지 본문, OTP, 알림 내용, 이미지나 credential을 기록하지 않으며, 필터 이력에는 발신자와 일반적인 필터 사유가 남을 수 있습니다. 민감한 내부 설정·운영 저장소는 Android backup/transfer 규칙에서 제외합니다.

6. JSON 백업과 내보내기

사용자는 설정을 JSON 파일로 저장하거나 Android 공유 기능으로 내보낼 수 있습니다. 연결정보 포함은 새 화면과 매 저장·공유 시작 시 기본 OFF입니다. 사용자가 해당 내보내기에서 명시적으로 ON한 경우에만 Telegram token/chat ID와 Discord webhook 등이 JSON에 포함될 수 있습니다.

설정 백업에는 선택 package 목록과 필터·자동화 설정 등이 포함될 수 있습니다. 메시지 본문·이미지, relay 이력, 진단과 pending 작업을 내보내는 기능은 아닙니다. credential 포함 JSON은 평문이며 앱 자체의 파일 암호화나 비밀번호 보호를 제공하지 않습니다. 안전한 저장 위치와 공유 대상을 선택하세요. 외부 파일이나 공유된 사본은 Studio Monmal이 삭제하거나 통제할 수 없습니다.

7. 설치 앱 정보와 기기 상태

알림 전달 대상을 사용자가 선택할 수 있도록 설치 앱 목록, 앱 label과 package 정보를 조회합니다. 전체 설치 앱 inventory를 Studio Monmal 서버로 업로드하지 않습니다. 선택 package는 로컬 설정에 저장되며, label 조회 실패 시 package 이름이 전달 메시지에 표시될 수 있습니다. 설정 JSON 내보내기에도 선택 package 목록이 포함될 수 있습니다.

사용자가 저배터리 알림 또는 기기 상태 보고 등 관련 기능을 활성화하면 사용자 설정 기기 표시명, Android/app version, 배터리·충전 상태가 Telegram/Discord로 전송될 수 있습니다.

8. 주요 권한과 목적

  • READ_SMS: MMS 내용·이미지 조회, SMS 재구성, 누락·정체 메시지 확인
  • RECEIVE_SMS: 신규 SMS 수신 이벤트 처리
  • RECEIVE_MMS: 신규 MMS 수신 이벤트 처리
  • Notification access: 사용자가 선택한 앱의 알림 전달
  • QUERY_ALL_PACKAGES: 알림 전달 대상으로 사용할 설치 앱을 사용자가 선택할 수 있도록 조회
  • POST_NOTIFICATIONS: 앱 자체 상태·실패 알림 표시

권한·접근 허용은 Android 설정에서 관리할 수 있습니다. 허용하지 않거나 해제하면 관련 기능이 제한됩니다. 이 설명은 Android 또는 Google Play의 권한 승인이나 출시 승인을 보장하지 않습니다.

9. 보존과 삭제

설정은 사용자가 변경하거나 앱 데이터를 삭제할 때까지 로컬에 남을 수 있습니다. pending 데이터와 진행·중복 방지 정보는 작업 완료, cleanup과 작업 상태에 따라 정리됩니다. 일부 작업이 지연되거나 실패하면 데이터가 더 오래 남을 수 있으며, 모든 항목에 고정 보존 기한을 약속하지 않습니다. 필터/relay 이력과 진단은 앱의 bounded 저장 규칙에 따라 관리됩니다.

  • 앱 전용 로컬 데이터: Android 설정 → 앱 → 알림전달자 → 저장공간 → 데이터 삭제 또는 앱 제거로 지울 수 있습니다. 메뉴 이름은 기기에 따라 다릅니다.
  • 외부로 내보낸 파일: 사용자가 해당 저장소와 공유 대상의 백업 파일·사본을 직접 삭제해야 합니다. 앱 데이터 삭제나 앱 제거로 자동 삭제되지 않습니다.
  • 이미 Telegram/Discord로 전송한 데이터: 해당 서비스에서 사용자가 관리하며 각 서비스 정책의 영향을 받습니다. 앱 데이터 삭제나 앱 제거가 이 데이터를 삭제하지 않습니다.

별도의 앱 계정 삭제 API는 없습니다. 로컬 데이터를 지워도 Android SMS/MMS provider의 원본 메시지를 삭제하는 기능은 아닙니다.

10. 보안과 광고·분석

Telegram/Discord 통신에는 HTTPS를 사용하고 내부 데이터는 앱 private storage에 보관합니다. 민감한 내부 저장소는 Android cloud backup/device transfer에서 제외하며 credential 내보내기는 명시적 opt-in입니다. 앱 자체의 추가 credential 암호화는 제공하지 않습니다. 사용자는 기기 접근과 전달 대상·백업 파일을 안전하게 관리해야 합니다.

현재 앱 코드에는 광고 SDK, analytics SDK, crash reporting SDK 또는 Studio Monmal relay backend가 없습니다. 이 설명은 Telegram/Discord나 OS의 처리를 대신 설명하는 것이 아닙니다. 이러한 SDK나 데이터 처리를 추가하면 방침과 필요한 스토어 Data Safety 안내를 갱신합니다.

1. Scope and developer

This policy applies to Notification Relay (알림전달자), the Android app developed and published by Studio Monmal. The app forwards SMS/MMS and selected-app notifications to Telegram or Discord according to your settings. It has no app signup/account system or Studio Monmal user-data server. Privacy contact: studiomonmal@gmail.com.

2. SMS and MMS access and use

For SMS relay, the app may process the sender, message body, receive time and available receiving-number/SIM information. New SMS events arrive through Android broadcasts. The app may re-query the Android SMS provider to reconstruct or recover some missed or stalled messages.

For MMS relay, the app may process the sender, text, images, MIME/attachment metadata and reception information. It reads text and images through the Android Telephony provider. Provider consistency audits for missed or stalled events may query recent provider data, so access is not limited to new broadcasts. Recovery is limited and does not guarantee recovery of every missed message.

3. Notification access and filters

The app checks early exclusions and application selection using minimal metadata supplied by Android, such as the package and notification flags. Only for apps selected for relay does it use package/application identity, app name, title, text/bigText, subText and processing time for relay. It does not extract notification content from non-selected apps for relay. Notification images and attachments are not relayed.

Your SMS/MMS sender rules, message-body keywords, notification include/exclude conditions and selected application packages determine relay eligibility. Notification exclude conditions take precedence over include conditions.

4. Transmission outside the device and third-party services

Eligible data is sent over HTTPS to the Telegram Bot API or Discord webhook that you configure. Depending on your delivery policy, it may be sent to one or both services, or to Discord after a permanent Telegram failure. Normal relay does not pass through a Studio Monmal relay server; Studio Monmal does not upload or retain message contents on its own server through this flow.

Relayed messages, images and related metadata leave your device. Subsequent Telegram/Discord processing, retention and access by others depend on those services' policies and your account, chat/channel and sharing settings. Check that you are authorized to send the data to your chosen destinations.

5. Connection credentials and local storage

Your Telegram bot token, Telegram chat ID, Discord webhook URL and settings are stored in app-private storage on your device. The app currently has no additional credential-encryption layer. The settings store is excluded from Android cloud backup and device transfer.

Reliable background delivery, retries, deduplication and recovery may temporarily store data locally, including pending SMS sender/body WorkManager input, pending notification payloads, relay progress metadata, filter history and health/recovery metadata. History and diagnostics do not record message bodies, OTPs, notification content, images or credentials; filter history may retain the sender and a generic filter reason. Sensitive internal configuration and operational stores are excluded by Android backup/transfer rules.

6. JSON backup and export

You can save settings as JSON or export them using Android sharing. Credential inclusion defaults to OFF on a fresh screen and at the start of each save/share action. Telegram token/chat ID and Discord webhook information can be included only when you explicitly turn inclusion ON for that export.

Settings exports may contain selected packages, filters and automation settings. They do not export message bodies/images, relay history, diagnostics or pending work. Credential-inclusive JSON is plaintext, without app-provided file encryption or password protection. Choose safe storage and sharing destinations. Studio Monmal cannot delete or control external files or shared copies.

7. Installed applications and device status

The app queries installed apps, labels and package information so that you can select notification relay sources. It does not upload the complete installed-app inventory to a Studio Monmal server. Selected packages are stored in local settings; a package name may appear in a relay message if label lookup fails. Selected packages may also appear in an exported settings JSON.

If you enable related features such as low-battery alerts or device status reports, your configured device display name, Android/app version, battery status and charging state may be sent to Telegram/Discord.

8. Main permissions and purposes

  • READ_SMS: Read MMS content/images, reconstruct SMS, and check missed or stalled messages
  • RECEIVE_SMS: Handle new SMS reception events
  • RECEIVE_MMS: Handle new MMS reception events
  • Notification access: Relay notifications from apps you select
  • QUERY_ALL_PACKAGES: Query installed apps so that you can choose notification relay sources
  • POST_NOTIFICATIONS: Display the app's own status/failure notifications

You can manage permissions/access in Android settings. Denying or revoking access limits related functions. This explanation does not guarantee permission approval or publication approval by Android or Google Play.

9. Retention and deletion

Settings may remain locally until you change them or clear app data. Pending data and progress/deduplication records are cleaned according to work completion, cleanup and work state. Delayed or failed work may retain data longer; no fixed retention period is promised for every item. Filter/relay history and diagnostics follow the app's bounded storage rules.

  • App-private local data: Use Android Settings → Apps → Notification Relay → Storage → Clear data, or uninstall. Menu names vary by device.
  • Exported files: Delete backup files and copies from their storage and sharing destinations yourself. Clearing app data or uninstalling does not automatically delete them.
  • Data already sent to Telegram/Discord: Manage it in those services, subject to their policies. Clearing app data or uninstalling does not delete it.

There is no separate app account-deletion API. Clearing local app data does not delete original messages in the Android SMS/MMS provider.

10. Security, advertising and analytics

Telegram/Discord communication uses HTTPS and internal data uses app-private storage. Sensitive internal stores are excluded from Android cloud backup/device transfer, and credential exports require explicit opt-in. No additional app-level credential encryption is provided. Secure your device, destinations and backup files.

The current app code includes no advertising SDK, analytics SDK, crash-reporting SDK or Studio Monmal relay backend. This does not describe processing by Telegram/Discord or the OS. If such SDKs or data processing are added, this policy and required store Data Safety information will be updated.
