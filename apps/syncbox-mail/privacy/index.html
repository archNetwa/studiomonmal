1. 적용 범위와 처리 주체

이 방침은 Studio Monmal이 관리하는 Chrome 확장 프로그램 SyncBox Mail에 적용됩니다. 같은 Chrome 프로필에서 로그인한 Gmail 계정의 읽지 않은 메일을 조회하고, 미리보기·배지·알림과 사용자가 선택한 메일 관리 기능을 제공합니다. 데이터는 사용자 브라우저와 Google 서비스에서 처리합니다.

2. 처리하는 데이터와 사용 목적

  • 계정과 인증 정보. Gmail 이메일 주소, Google 계정 식별자와 로그인 계정의 세션 순서로 계정을 감지하고 확인합니다. 사용자가 메일 처리 기능을 실행하고 Chrome의 선택적 쿠키 권한을 허용하면, 선택한 계정 경로의 Gmail 작업 토큰과 Gmail 페이지의 메일 처리용 식별정보를 사용합니다. 이 정보는 해당 계정의 읽음·보관·휴지통 요청을 Gmail에 보내는 데 사용합니다. 별도의 Google 권한 연결을 선택하면 Chrome Identity가 제공한 OAuth 액세스 토큰을 Google API 요청에 사용합니다.
  • 이메일과 Gmail 웹사이트 콘텐츠. 계정 주소, 발신자·수신자 등의 메일 헤더, 제목, 수신 시각, 메시지·대화 식별자, 읽음·받은편지함 상태, 읽지 않은 메일 수와 본문 미리보기를 조회합니다. Gmail 페이지의 로그인 계정 목록과 받은편지함 피드에서 필요한 정보를 추출하며, 직접 조회가 어려우면 열린 Gmail 탭에서 계정과 받은편지함 정보를 읽습니다. 이 정보는 계정 목록, 네 가지 메일 보기, 배지와 알림에 사용합니다.
  • 사용자 설정과 동작. 화면 모드, 메일 보기 방식, 알림 사용 여부와 계정 표시 순서를 저장합니다. 읽음·보관·휴지통과 계정별 읽음 정리는 사용자가 선택한 계정에서 실행합니다. 웹 로그인 세션에서는 받은편지함을 재확인하고 한 번에 최대 15통씩 나누어 처리하며, 많은 메일은 Gmail 화면에서 직접 관리할 수도 있습니다. 편지쓰기는 선택한 계정의 Gmail 작성 창을 열며, 작성 내용과 받는 사람은 Gmail에서 입력하고 발송합니다.

3. 통신과 제3자 처리

메일 조회는 mail.google.com과 gmail.googleapis.com, OAuth 계정 확인은 openidconnect.googleapis.com에 HTTPS로 직접 요청합니다. 사용자가 계정 로그인을 선택하면 accounts.google.com의 Google 로그인 화면을 엽니다. 웹 세션으로 메일을 처리할 때는 열린 Gmail 탭을 사용하며, 필요한 경우 백그라운드 Gmail 탭을 임시로 열어 연결합니다. 완료 후 사용 중이 아닌 임시 탭은 닫습니다. OAuth 연결에는 gmail.modify와 openid 범위를 사용합니다.

Studio Monmal은 확장의 이메일·계정 정보·토큰을 수집하는 서버를 운영하지 않습니다. 확장 데이터는 광고, 분석 추적, 데이터 판매, 신용도 판단·대출 또는 AI 학습에 사용하지 않으며 이러한 목적으로 제3자에게 제공하지 않습니다. Chrome과 운영체제는 알림 표시를 위해 제목·보낸 사람·본문 미리보기·계정 주소를 처리할 수 있습니다. 알림은 사용자가 설정에서 끌 수 있습니다.

4. 저장 위치와 보존 기간

chrome.storage.local에는 OAuth 연결 계정의 주소와 식별자, 감지된 계정 식별자, 설정과 표시 순서, 메일 조회의 변경 이력 위치, 확인 시각, 알림 중복 방지를 위한 메시지·대화 식별자 등의 기록을 보관합니다. 메일 제목·보낸 사람·본문 미리보기는 chrome.storage.session에 보관합니다. 이 세션 데이터는 Chrome 재시작 또는 확장 재로드 시 초기화됩니다.

알림 중복 방지와 웹 계정 확인용 영구 기록은 메일 조회가 성공적으로 갱신될 때 7일을 넘긴 항목을 정리하며, 알림 기록은 최대 150개, 웹 계정 확인 기록은 최대 50개를 유지합니다. 계정 표시 순서와 환경설정은 확장을 제거할 때까지 유지될 수 있습니다. OAuth 액세스 토큰은 Chrome이 관리합니다. 확장은 Gmail 작업 토큰·메일 처리용 식별정보·OAuth 액세스 토큰을 실행 메모리에서만 사용하고 자체 저장소에 기록하지 않습니다. 로컬 데이터 보호는 Chrome 프로필과 운영체제의 접근 통제에 의존합니다.

5. 접근 중단과 삭제

자동 감지를 중단하려면 해당 Chrome 프로필의 Gmail에서 로그아웃하거나 확장을 사용 중지·제거하세요. Chrome의 확장 프로그램 세부정보에서 Gmail 사이트 접근을 제한해 웹 세션 접근을 중단할 수도 있습니다. 확장의 계정 및 설정에서 OAuth 연결을 해제하면 해당 연결 계정과 메일 캐시를 정리합니다. Gmail 로그인이 유지된 계정은 자동 감지에 계속 나타날 수 있습니다. Google 서버의 접근 권한을 철회하려면 Google 계정의 서드 파티 연결에서 승인한 앱의 액세스를 삭제하세요.

확장을 제거하면 해당 Chrome 프로필의 확장 저장 데이터가 삭제됩니다. Gmail 원본 메일과 이미 변경한 읽음·보관·휴지통 상태는 Gmail에서 관리하며, 운영체제에 남은 알림은 알림 센터에서 따로 지울 수 있습니다.

6. Google 데이터의 제한적 사용

Google API에서 받은 정보는 이 방침에 기재한 Gmail 조회·알림·메일 관리 기능을 제공하는 데 사용합니다. 정보의 사용과 이전은 Google API 서비스 사용자 데이터 정책의 제한적 사용(Limited Use) 요건과 Chrome 웹 스토어 사용자 데이터 정책을 준수합니다.

7. Chrome 권한의 목적

  • identity는 사용자가 선택한 Google 권한 연결과 OAuth 토큰 요청에 사용합니다.
  • 선택적 cookies 권한은 사용자가 Gmail 로그인 세션으로 메일을 처리할 때 요청합니다. 선택한 계정 경로에 해당하는 Gmail 작업 토큰만 읽으며, 이를 해당 Gmail의 메일 변경 요청에 사용합니다.
  • alarms는 Chrome 실행 중 기본 30초 간격으로 Gmail을 확인하는 작업을 예약합니다. 실행 시점은 Chrome·기기·네트워크 상태에 따라 지연될 수 있습니다.
  • notifications는 새 메일과 사용자가 요청한 테스트 알림을 표시합니다.
  • storage는 계정·설정·조회 상태를 로컬에 저장하고 메일 미리보기를 세션에 보관합니다.
  • Gmail 호스트 접근과 콘텐츠 스크립트는 로그인 계정·읽지 않은 메일 조회 및 사용자가 선택한 계정의 메일 처리에 사용합니다. 계정 주소를 재확인한 뒤 지정된 Gmail 계정 페이지·받은편지함 피드·메일 동작 주소로만 요청합니다. Gmail API와 OpenID Connect 호스트 접근은 승인된 계정의 메일 작업과 계정 확인에 사용합니다.

1. Scope and operator

This policy applies to SyncBox Mail, a Chrome extension managed by Studio Monmal. It checks unread messages for Gmail accounts signed into the same Chrome profile and provides previews, badges, notifications, and mailbox actions selected by the user. Data is processed in your browser and through Google services.

2. Data and purposes

  • Account and authentication information. Gmail addresses, Google account identifiers, and account session order identify and verify accounts. When you choose a mail action and grant Chrome's optional cookie permission, the extension uses the Gmail action token for the selected account path and mail-action identifiers from Gmail pages. They authorize read, archive, and trash requests to Gmail for that account. If you separately connect Google permissions, Chrome Identity provides an OAuth access token for Google API requests.
  • Email and Gmail website content. The extension reads account addresses, mail headers such as senders and recipients, subjects, timestamps, message and thread identifiers, read and inbox status, unread counts, and message snippets. It extracts the required information from Gmail account pages and inbox feeds. If direct access fails, it reads account and inbox information through an open Gmail tab. This data supports account lists, four mailbox views, badges, and notifications.
  • Preferences and actions. Theme, mailbox view, notification preference, and account order are stored. Read, archive, trash, and inbox cleanup run only for the account selected by the user. The web-session path rechecks the inbox and processes up to 15 messages at a time. You can also manage larger amounts directly in Gmail. Composing opens the selected account's Gmail compose window. You enter recipients and message content and send the message in Gmail.

3. Connections and third-party processing

Mail requests go directly over HTTPS to mail.google.com and gmail.googleapis.com. OAuth account verification uses openidconnect.googleapis.com. Choosing account sign-in opens Google's sign-in page at accounts.google.com. Web-session actions use an open Gmail tab or temporarily open a background Gmail tab if needed. A temporary tab is closed after the operation when it is not in active use. OAuth connections request gmail.modify and openid.

Studio Monmal operates no server that collects extension emails, account data, or tokens. Extension data is not used or provided to third parties for advertising, analytics tracking, data sales, creditworthiness or lending decisions, or AI training. Chrome and the operating system may process subjects, senders, snippets, and account addresses to display notifications. You can turn notifications off in settings.

4. Storage and retention

chrome.storage.local holds connected account addresses and identifiers, detected account identifiers, preferences and account order, mail history cursors, check timestamps, and message and thread identifiers used to prevent duplicate notifications. Subjects, senders, and snippets are held in chrome.storage.session, which is cleared when Chrome restarts or the extension reloads.

A successful mailbox refresh removes notification and web-account tracking entries older than seven days and limits these records to 150 notifications and 50 web-account entries. Account order and preferences may remain until the extension is removed. Chrome manages OAuth access tokens. The extension uses Gmail action tokens, mail-action identifiers, and OAuth tokens only in execution memory and does not write them to its own storage. Local data protection relies on Chrome profile and operating-system access controls.

5. Stopping access and deleting data

Stop automatic detection by signing out of Gmail in the same Chrome profile or disabling or removing the extension. Restricting Gmail site access in Chrome's extension details also stops web-session access. Disconnecting an OAuth account in extension settings removes that connection and its mail cache. An account still signed into Gmail can remain visible through automatic detection. Revoke server-side Google permissions through third-party connections in your Google Account.

Removing the extension deletes its stored data in that Chrome profile. Manage original messages and read, archive, or trash changes in Gmail. Clear operating-system notifications separately in your notification center.

6. Google data and Limited Use

Information received from Google APIs is used for the Gmail viewing, notification, and mailbox actions described here. Its use and transfer comply with the Limited Use requirements of the Google API Services User Data Policy and the Chrome Web Store User Data Policy.

7. Chrome permissions

  • identity supports Google authorization and OAuth token requests initiated by the user.
  • Optional cookies permission is requested when you choose a mail action using your Gmail sign-in session. It reads the Gmail action token for the selected account path and uses it for that account's Gmail mail-change requests.
  • alarms schedules mailbox checks every 30 seconds while Chrome runs. Chrome, device conditions, or connectivity may delay execution.
  • notifications displays new-mail notices and user-requested test notifications.
  • storage keeps accounts, preferences, and check state locally and mail previews in session storage.
  • Gmail host access and content scripts support reading signed-in accounts and unread mail and applying user-selected mailbox actions. After rechecking the account address, requests are limited to fixed Gmail account pages, inbox feeds, and mail-action endpoints. Gmail API and OpenID Connect host access support authorized mailbox actions and account verification.
