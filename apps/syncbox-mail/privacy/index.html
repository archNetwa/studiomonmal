1. 적용 범위와 처리 주체

이 방침은 Studio Monmal이 관리하는 Chrome 확장 프로그램 SyncBox Mail에 적용됩니다. 같은 Chrome 프로필에 로그인된 Gmail 계정을 찾아 읽지 않은 메일과 전체 본문을 표시하고, 새 메일 알림·읽음 처리·휴지통·편지쓰기 기능을 제공합니다. 데이터는 사용자 브라우저와 Google 서비스에서 처리합니다.

조회 전 동의. 처음 실행하거나 기존 설치본에 현재 데이터 이용 안내의 동의 기록이 없으면 앱 안에서 조회 범위·본문 사전 준비·자동 읽음·보관 방식을 안내합니다. 사용자가 ‘동의하고 시작’을 선택하고 동의 기록 저장이 완료되기 전에는 계정 탐색, 메일·본문 조회, 인증 토큰 요청과 메일 알림을 시작하지 않습니다. ‘동의하지 않음’을 선택하거나 안내창을 닫으면 조회하지 않습니다. 동의한 안내의 버전과 시각만 chrome.storage.local에 저장하며 확장 제거 전까지 유지할 수 있습니다. 선택적 쿠키 권한과 Google OAuth 승인은 필요한 기능을 사용할 때 별도로 요청합니다.

2. 처리하는 데이터와 사용 목적

  • 계정과 인증 정보. Gmail 주소, Google 계정 식별자와 웹 로그인 세션 순서로 계정을 감지하고 확인합니다. Gmail 로그인 세션으로 메일을 처리할 때는 Chrome의 선택적 쿠키 권한을 요청하고, 선택 계정 경로의 Gmail 작업 토큰과 Gmail 페이지의 처리용 식별정보를 사용합니다. 별도의 Google 권한 연결을 선택하면 Chrome Identity가 제공하는 OAuth 액세스 토큰으로 Gmail API와 계정 확인 API를 호출합니다. Google 비밀번호를 읽거나 저장하지 않습니다.
  • 이메일과 웹사이트 콘텐츠. 계정 주소, 발신자·수신자 등의 헤더, 제목, 수신 시각, 메시지·대화 식별자, 읽음·받은편지함 상태, 읽지 않은 메일 수, 미리보기와 전체 본문을 조회합니다. 웹 로그인 경로는 Gmail 페이지·받은편지함 피드·메일 인쇄 응답을 사용하며, OAuth 연결 경로는 Gmail API와 필요한 텍스트 본문 파트를 사용합니다. 직접 받은편지함 조회가 어려우면 이미 열린 Gmail 탭에서 제한된 계정·피드 정보를 읽습니다.
  • 빠른 본문 표시. 클릭 후 대기 시간을 줄이기 위해 메일 갱신이 끝난 뒤 계정별 최근 두 항목을 돌아가며 최대 12개 본문을 백그라운드에서 미리 조회할 수 있습니다. 미리 조회하는 것만으로 읽음 변경 요청을 보내지는 않습니다. 표시할 본문을 해석할 때 스크립트·폼·프레임·원격 CSS와 외부 이미지의 실행·자동 로딩을 차단합니다.
  • 메일 변경. 사용자가 메일을 열어 전체 본문이 정상 표시되면 Gmail에도 읽음 변경을 요청합니다. 본문 표시 전 목록으로 돌아가거나 본문 조회가 실패하면 자동 읽음 요청을 보내지 않습니다. 실패하면 오류를 알리고 남은 메일을 다시 표시합니다. 개별 읽음·휴지통과 계정별 읽음 정리도 사용할 수 있습니다. 읽음 정리는 실행 시점까지 도착한 메일을 대상으로 하며 웹 세션에서는 최대 15통씩 나누어 처리합니다.
  • 알림과 작성 창. 알림의 읽음·휴지통 버튼은 알림 제목에 표시된 한 통에 적용하며, 알림 닫기는 메일 상태를 바꾸지 않습니다. 편지쓰기는 선택한 계정의 작은 Gmail 작성 창을 엽니다. 받는 사람과 내용은 사용자가 Gmail에서 입력·확인·발송합니다. 앱이 연 작성 창에 한해 보내기 동작과 Gmail의 발송 완료 표시를 감지해 창을 닫습니다. 이 감지 기능은 입력 중인 본문이나 받는 사람 입력값을 기록하지 않습니다.
  • 설정. 화면 모드, 네 가지 메일 보기, 알림 사용 여부와 계정 순서를 저장합니다.

3. 통신과 제3자 처리

메일 요청은 HTTPS로 mail.google.com과 gmail.googleapis.com에 직접 전송하며, OAuth 계정 확인에는 openidconnect.googleapis.com을 사용합니다. 사용자가 계정 추가를 선택하면 accounts.google.com의 Google 화면을 엽니다. OAuth 연결 범위는 gmail.modify와 openid입니다.

기존 Gmail 세션의 작업 정보가 준비되지 않았을 때 Chrome Identity의 비대화형 Google 페이지 뷰를 잠시 사용해 세션을 준비할 수 있습니다. 이 과정에서 별도의 Gmail 탭을 자동으로 만들거나 사용자 대신 새 로그인·OAuth 승인을 완료하지 않습니다. 메일 변경은 확장의 백그라운드에서 Google로 직접 보냅니다. 읽지 않은 메일의 변경은 피드를 다시 조회해 확인하며, 이미 읽은 메일의 휴지통은 피드로 라벨 변화를 확인할 수 없어 서버 요청 접수 결과로 안내합니다.

Studio Monmal은 확장의 이메일·계정 정보·토큰을 수집하는 서버를 운영하지 않습니다. 확장 데이터는 광고, 분석 추적, 판매, 신용도 판단·대출이나 AI 학습에 사용하거나 그러한 목적으로 제공하지 않습니다. Chrome과 운영체제는 알림 표시를 위해 제목·보낸 사람·본문 미리보기·계정 주소를 처리할 수 있습니다. 알림은 설정에서 끌 수 있습니다.

4. 저장 위치와 보존·정리

  • 기기 내 저장. chrome.storage.local에는 OAuth 연결 계정의 주소·식별자, 감지된 계정 식별자, 설정·계정 순서, 조회 이력 위치와 확인 시각, 알림 중복 방지용 메시지·대화 식별자와 처리 상태를 저장합니다. 성공한 메일 갱신 시 7일을 넘긴 알림·웹 계정 확인 기록을 정리하고, 각각 최대 150개·50개로 제한합니다. 설정과 계정 순서는 제거 전까지 남을 수 있습니다.
  • 세션 메모리. 메일 목록·헤더·미리보기와 준비한 본문은 chrome.storage.session에 보관하며 local이나 sync에 전체 본문을 저장하지 않습니다. 공유 본문 캐시는 재사용 유효기간 5분·최대 12개·앱의 크기 계산 기준 합계 약 4MiB로 제한합니다. 만료·계정 변경·목록 변경은 다음 조회·갱신·정리 시 반영하며, 상한을 넘은 항목은 보관하지 않거나 오래된 항목부터 정리합니다.
  • 읽기 화면과 처리 기록. 열어 둔 본문과 최근 읽기 화면의 앞·뒤 이동에 필요한 본문은 현재 확장 페이지의 메모리에도 남을 수 있으며 해당 페이지를 닫거나 다시 로드하면 초기화됩니다. 읽음 후 휴지통 처리를 위해 계정·세션 순서·메시지·대화 식별자·시각·읽음 확인 여부와 앱 내부 연결 식별자를 세션에 최대 24개 보관합니다. 처리 권한은 30분만 유효하며, 새 열람·처리 시 만료 기록을 정리합니다. 이 기록에는 본문·제목·Google 인증 토큰을 넣지 않습니다.
  • 작성 창. 자동 닫기를 위해 앱이 연 창·탭의 식별자와 앱 내부 연결 식별자를 세션에 최대 40개 보관하고 해당 창·탭이 닫히면 정리합니다.

세션 저장소는 메모리 영역이며 Chrome 재시작 또는 확장의 중지·재로드·업데이트 시 초기화됩니다. 시간 제한은 캐시 재사용 또는 처리 허용 기간이며, 모든 기록이 해당 시각에 즉시 물리적으로 삭제된다는 뜻은 아닙니다. OAuth 액세스 토큰은 Chrome이 관리합니다. 확장은 Gmail 작업 토큰·Gmail 페이지의 작업 세션 키·OAuth 액세스 토큰을 실행 메모리에서만 사용하고 자체 저장소에 기록하지 않습니다. 로컬 데이터 보호는 Chrome 프로필과 운영체제의 접근 통제에 의존합니다.

자동 감지를 중단하려면 같은 Chrome 프로필의 Gmail에서 로그아웃하거나 확장을 중지·제거하세요. 확장 세부정보에서 Gmail 사이트 접근을 제한하거나 선택적 쿠키 권한을 철회하면 관련 웹 접근·메일 처리를 제한할 수 있습니다. OAuth 연결을 해제하면 해당 연결과 메일 캐시를 정리하지만, Gmail 웹 로그인이 유지된 계정은 자동 감지에 계속 나타날 수 있습니다. Google의 서버 측 권한은 Google 계정의 서드 파티 연결에서 별도로 철회할 수 있습니다.

1. Scope and operator

This policy covers SyncBox Mail, a Chrome extension managed by Studio Monmal. It detects Gmail accounts signed into the same Chrome profile, displays unread messages and full bodies, and provides notifications, read and trash actions, and composing. Data is processed in your browser and through Google services.

Consent before access. On first use, or when an existing installation has no record accepting the current disclosure, the app explains account/mail access, body preparation, automatic read and storage. Account discovery, mail/body queries, authentication-token requests and mail notifications do not start until you select “Agree and start” and the consent record is saved. Declining or closing the disclosure leaves access paused. Only the accepted disclosure version and timestamp are stored in chrome.storage.local and may remain until uninstall. Optional cookie access and Google OAuth authorization are requested separately when needed.

2. Data and purposes

  • Accounts and authentication. Gmail addresses, Google account identifiers and web-session order identify and verify accounts. Web-session mail actions request Chrome's optional cookie permission and use the Gmail action token for the selected account path and mail-action identifiers from Gmail pages. Optional Google authorization uses OAuth access tokens supplied by Chrome Identity for Gmail and account-verification APIs. The extension does not read or store Google passwords.
  • Email and website content. The extension reads account addresses, sender/recipient headers, subjects, timestamps, message/thread identifiers, read and inbox status, unread counts, snippets and full bodies. The web path uses Gmail account pages, inbox feeds and message-print responses; the OAuth path uses Gmail APIs and required text body parts. If direct inbox queries fail, limited account/feed information can be read through an already-open Gmail tab.
  • Preparing bodies. To reduce waiting after a click, mailbox refreshes can prepare up to 12 bodies in the background, taking recent items in turn from up to two per account. Preparation alone sends no mark-as-read request. Body rendering blocks scripts, forms, frames, remote CSS and automatic external-image loading.
  • Mail changes. Opening a message and successfully displaying its full body triggers a mark-as-read request to Gmail. Returning to the list before display or a failed body load does not trigger automatic read. Errors are shown and remaining messages are restored. Individual Read/Trash and account-specific inbox cleanup are also available. Cleanup targets messages received by its start time; the web path handles up to 15 at a time.
  • Notifications and compose. Read/Trash buttons on a notification affect the single message in its title; closing a notification does not change mail. Composing opens a small Gmail window for the selected account. You enter, review and send recipients and content in Gmail. Only in app-opened compose windows, the extension detects the send action and Gmail's sent confirmation to close the window. This detection does not record the draft body or recipient input values.
  • Preferences. Theme, four mailbox views, notification preference and account order are saved.

3. Connections and third-party processing

HTTPS mail requests go directly to mail.google.com and gmail.googleapis.com; OAuth account verification uses openidconnect.googleapis.com. Choosing account sign-in opens Google's accounts.google.com page. OAuth requests use gmail.modify and openid.

When existing Gmail action-session information is unavailable, Chrome Identity may briefly use a non-interactive Google page view to prepare the session. This does not automatically create a separate Gmail tab or complete a new sign-in or OAuth approval for you. Mail changes go directly to Google from the background worker. Unread changes are checked through another inbox query. For an already-read message, an unread-only feed cannot verify its Trash label, so the extension reports server request acceptance.

Studio Monmal operates no server collecting extension emails, account data or tokens. Extension data is not used or provided for advertising, analytics tracking, data sales, credit/lending decisions or AI training. Chrome and the operating system may process subjects, senders, snippets and account addresses to display notifications. Notifications can be disabled in settings.

4. Storage and cleanup

  • On-device storage. chrome.storage.local stores connected account addresses/identifiers, detected account identifiers, preferences/order, history cursors/check timestamps and notification-deduplication message/thread identifiers and action status. Successful refreshes remove notification/web-account records older than seven days, with limits of 150 and 50 respectively. Settings/order can remain until uninstall.
  • Session memory. Lists, headers, snippets and prepared bodies use chrome.storage.session. Full bodies are not written to local or sync. The shared body cache has a five-minute reuse period, up to 12 items and about 4 MiB under the app's size calculation. Expiry, account/list changes are applied on subsequent queries, refreshes and cleanup. Items beyond the limits are excluded or oldest entries are removed.
  • Reader and action records. The currently displayed body and the recent reader used for Back/Forward may also remain in the current extension page's memory until that page closes or reloads. Up to 24 session records bind account/session order, message/thread identifiers, timestamps, read confirmation and an app-local correlation identifier for Trash after read. Their action validity is 30 minutes; opening/processing messages cleans expired records. These records contain no body, subject or Google authentication token.
  • Compose windows. Up to 40 app-created window/tab identifiers and app-local correlation identifiers are held in session storage for automatic closing and removed when the corresponding window/tab closes.

Session storage is in memory and clears when Chrome restarts or the extension is disabled, reloaded or updated. Time limits describe cache reuse or action validity, not guaranteed physical deletion at that exact instant. Chrome manages OAuth access tokens. Gmail action tokens, Gmail page action-session keys and OAuth tokens are used only in execution memory and are not written to the extension's own storage. Local protection relies on Chrome-profile and operating-system access controls.

5. Stopping access and deletion

Stop automatic detection by signing out of Gmail in the same Chrome profile or disabling/removing the extension. Restricting Gmail site access or revoking the optional cookie permission in extension details limits related web access/actions. Disconnecting OAuth removes that connection and mail cache, but an account still signed into Gmail may remain automatically visible. Revoke Google's server-side permissions separately through Google third-party connections.

Uninstalling deletes extension storage in that profile. Original Gmail messages and completed Read/Trash changes are managed in Gmail. Clear operating-system notifications separately.

7. Chrome permissions

  • identity: optional Google OAuth/token requests and non-interactive preparation of an existing Gmail web session.
  • Optional cookies: requested when opening a web-account message or using mail actions. It reads the selected account path's Gmail action token for that account's Read/Trash requests. Denial can prevent automatic read and shows guidance.
  • alarms: schedules checks every 30 seconds while Chrome runs. Device, Chrome or network conditions may delay them.
  • notifications: displays new mail, action errors and user-requested tests.
  • storage: on-device accounts/preferences/check state and session-memory mail lists, bodies and action records.
  • Gmail host access: account/feed/full-body queries and selected-account mail changes. Gmail content scripts perform limited queries in open tabs and detect sent confirmations in app-opened compose windows. Gmail API/OpenID Connect hosts support authorized mail actions and account verification.
