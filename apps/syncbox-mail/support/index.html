계정 자동 감지와 새로고침

같은 Chrome 프로필에서 Gmail에 로그인한 계정을 사용합니다. 계정이 빠졌다면 Google의 현재 로그인 계정 목록을 확인한 뒤 앱의 새로고침을 누르세요. Gmail 탭을 계속 열어 둘 필요는 없습니다. 이미 열린 Gmail 탭이 있으면 직접 조회 실패 시 제한된 계정·피드 조회에 이용할 수 있습니다.

본문 열기와 자동 읽음

메일 제목이나 미리보기를 누르면 같은 확장 화면에서 전체 본문을 엽니다. 본문이 정상 표시되면 Gmail에도 읽음 변경을 요청하고, 목록 복귀 시 해당 메일과 안 읽음 숫자를 갱신합니다. 읽는 중에도 본문은 유지됩니다. 본문 표시 전에 뒤로 가거나 로딩이 실패하면 자동 읽음 요청을 보내지 않습니다. 요청이 실패하면 오류를 확인하고 읽음 버튼으로 다시 시도할 수 있습니다.

웹 로그인 계정의 본문을 처음 열거나 메일 처리 기능을 사용할 때 Chrome이 선택적 Gmail 쿠키 접근을 요청할 수 있습니다. 거절하면 자동 읽음이 적용되지 않을 수 있습니다. 별도 Google 권한 연결도 선택할 수 있습니다. 추가 Google 승인 여부는 실제 Google 화면을 확인하고 결정하세요.

개별 처리와 계정별 읽음 정리

목록·읽기 화면의 읽음과 휴지통을 사용합니다. 휴지통은 확인 창에서 취소할 수 있으며 영구 삭제 기능이 아닙니다. 통합 타임라인의 읽음 정리에서 계정을 선택하거나 계정별 목록의 읽음 정리를 누르면 주소와 안 읽은 수를 확인할 수 있습니다. 웹 세션은 최대 15통씩 나누어 처리하고 실행 중 새로 도착한 메일은 남깁니다. 일부 실패 시 완료 건수와 남은 상태를 확인한 뒤 재시도하세요.

이미 읽은 메일의 웹 세션 휴지통 요청은 안 읽은 피드로 라벨 변화를 확인할 수 없어 서버 접수 결과로 안내합니다. 상태가 불명확하면 Gmail에서 해당 메일을 확인하세요. 로그인 계정이 변경됐거나 읽기 연결이 만료되면 원래 계정을 확인하고 목록을 새로고침하세요.

빠른 표시와 이미지

최근 본문을 미리 조회해 세션 메모리에 준비하므로 준비된 메일은 빠르게 열립니다. 새로 도착했거나 준비 범위를 벗어난 메일은 추가 조회가 필요할 수 있습니다. 외부 이미지·스크립트·원격 CSS는 본문에서 자동으로 불러오지 않습니다. 자세한 보관·정리 기준은 개인정보처리방침을 참고하세요.

Windows 알림

설정에서 Windows 데스크톱 알림을 켜고 알림 테스트를 누르세요. Chrome 접수 메시지가 보여도 배너 표시는 Windows 알림 설정·알림 센터·집중 모드 등에 영향을 받습니다. 알림의 읽음·휴지통은 제목에 표시된 한 통에 적용하고, 닫기(X)는 알림만 닫습니다. 알림 본문은 해당 메일을 Gmail에서 엽니다. 테스트 알림의 버튼은 실제 메일을 변경하지 않습니다. 쿠키 권한이 필요한 계정은 먼저 앱에서 허용해야 알림 버튼으로도 처리할 수 있습니다.

발신 계정과 작성 창 자동 닫기

메일 쓰기에서 보내는 계정을 고르세요. 하나뿐이면 바로 그 계정의 작은 Gmail 작성 창을 엽니다. 받는 사람·내용·보내는 주소는 Gmail에서 직접 확인하고 발송합니다. 앱이 연 작성 창에서 보내기 동작과 Gmail의 발송 완료 표시를 확인하면 창을 닫습니다. 전송 오류·미발송 초안·앱에서 열지 않은 Gmail 창은 자동으로 닫지 않습니다. Chrome/Google의 화면 변경으로 감지하지 못하면 발송 상태를 Gmail에서 확인하고 창을 직접 닫으세요.

뒤로가기와 업데이트

읽기 화면의 왼쪽 화살표, Esc, Alt+왼쪽과 마우스 뒤로 버튼으로 목록에 돌아갑니다. 현재 읽기 화면의 앞·뒤 이동 정보는 해당 확장 페이지를 닫거나 재로드하면 초기화됩니다. 압축해제 설치본은 chrome://extensions의 SyncBox Mail 카드에서 새로고침한 뒤 새 팝업으로 확인하세요. 앱 안의 메일 새로고침과 확장 자체의 재로드는 다릅니다.

접근 중단과 데이터 삭제

Gmail 로그아웃, Gmail 사이트 접근 제한, 쿠키 권한 철회 또는 확장 중지·제거로 관련 접근을 제한할 수 있습니다. OAuth의 서버 측 권한은 Google 계정의 서드 파티 연결에서 철회하세요. 확장을 제거하면 해당 Chrome 프로필의 확장 데이터가 삭제되며 Gmail 원본과 이미 변경한 상태는 Gmail에서 관리합니다.

Account detection and refresh

Use Gmail accounts signed into the same Chrome profile. If one is missing, check Google's signed-in account list and refresh the app. A Gmail tab does not need to stay open. An already-open Gmail tab may support limited account/feed queries when direct access fails.

Opening a body and automatic read

Select a subject or preview to open the full body in the same extension screen. A successfully displayed body triggers a mark-as-read request to Gmail, updating the unread list/count when you return. The body stays open while reading. Leaving before display or a failed body load does not trigger automatic read. If a change fails, check the error and retry with Read.

Chrome may request optional Gmail cookie access when first opening a web-account message or using mail actions. Denial can prevent automatic read. Separate Google authorization is also optional; review the actual Google approval screen before deciding.

Individual actions and inbox cleanup

Use Read/Trash in the list or reader. Trash has a cancelable confirmation and is not permanent deletion. Choose an account through timeline Inbox cleanup or use its account-view button to confirm the address and unread count. The web path handles up to 15 at a time and leaves messages arriving after cleanup starts. Review completed/remaining counts before retrying a partial failure.

For a web-session Trash request on an already-read message, the unread-only feed cannot verify the label change, so the app reports server acceptance. Check Gmail if the result is unclear. If an account changes or reader connection expires, verify the account and refresh the list.

Fast display and images

Recent bodies may be prepared in session memory for faster opening. New or unprepared messages can require another query. External images, scripts and remote CSS are not loaded automatically in the reader. See the Privacy Policy for retention and cleanup.

Windows notifications

Enable desktop notifications and select the test. Chrome accepting a notice does not guarantee a banner; Windows settings, notification center and focus modes affect display. Read/Trash affect the single message in the notification title; Close (X) only dismisses the notice. Clicking its body opens the message in Gmail. Test buttons never change real mail. Grant required cookie access in the app before using notification actions for web accounts.

Sender and compose-window closing

Choose a sender under Compose, or open the only account directly. Review recipients, content and the sending address in Gmail and send there. An app-opened compose window closes after the extension detects both sending and Gmail's sent confirmation. Send errors, unsent drafts and Gmail windows not opened by the app are not automatically closed. If Chrome/Google changes prevent detection, verify the send in Gmail and close the window yourself.

Back navigation and updates

Use the top-left arrow, Esc, Alt+Left or mouse Back to return to the list. Reader Back/Forward information resets when the extension page closes/reloads. For unpacked installs, reload SyncBox Mail at chrome://extensions and open a new popup. Mail refresh inside the app is separate from reloading the extension.

Stopping access and deletion

Sign out of Gmail, restrict Gmail site access, revoke cookie permission or disable/remove the extension to limit related access. Revoke OAuth server-side access through Google third-party connections. Uninstalling deletes extension data in that profile. Manage original mail and completed changes in Gmail.
