1. 적용 범위와 운영자

이 방침은 Studio Monmal이 관리하는 Chrome 확장 프로그램 SyncBox Calendar에 적용됩니다. 확장은 사용자가 연결한 Google 계정의 캘린더와 일정을 표시하고 일정 추가·수정·삭제, 알림과 다시 알림, 선택적인 Tasks 및 연락처 기능을 제공합니다. 데이터는 사용자 기기와 Google 서비스에서 처리합니다. 별도의 Studio Monmal 계정이나 일정 처리 서버는 없습니다.

2. 접근하는 데이터와 목적

  • 계정과 인증. Google 계정 식별자, 이메일 주소와 승인 범위를 이용해 계정을 확인하고 요청을 구분합니다. Chrome Identity가 제공한 OAuth 토큰은 Google API 호출에 사용합니다. Google 비밀번호를 앱에 입력하지 않습니다.
  • 캘린더와 일정. 캘린더 식별자·이름·색상·시간대·권한·기본 알림, 일정 제목·날짜·시간·장소·설명·참석자·반복·공개 범위·알림 설정과 변경 식별정보를 읽습니다. 이 데이터는 달력, 검색, 일정 요약과 편집, 배지, 알림 및 동기화에 사용합니다. 사용자가 저장·삭제한 내용은 Google Calendar에 반영됩니다. 참석자에게 변경 메일 보내기를 선택하면 Google이 해당 변경을 참석자에게 전달할 수 있습니다.
  • 선택적 작업과 연락처. 사용자가 추가 Google 권한을 승인하면 Google Tasks의 목록·제목·메모·기한·완료 상태를 읽고 요청한 변경을 반영합니다. 연락처 권한은 참석자 입력의 검색/자동 완성을 위해 이름과 이메일 주소를 읽는 데 사용합니다.
  • 직접 입력과 설정. 사용자가 선택 메뉴나 주소창 기능에 입력·전달한 텍스트를 일정 초안으로 사용합니다. 일반 웹사이트의 방문 기록·페이지 본문을 자동 수집하거나 웹 페이지에 코드를 삽입하지 않습니다. 테마, 표시 방식, 알림 설정, 다시 알림 시각과 사용자가 선택한 설정 백업을 처리합니다.

3. Google 연결과 제3자 처리

계정 확인과 Calendar API는 www.googleapis.com, Tasks는 tasks.googleapis.com, 연락처 검색은 people.googleapis.com에 HTTPS로 직접 연결합니다. 로그인과 승인, 토큰 캐시는 Chrome Identity 및 Google이 관리합니다. 기본 Google 권한은 캘린더 읽기, 일정 관리와 이메일 확인이며 캘린더 목록 변경·Tasks·연락처 읽기는 해당 기능에서 별도 승인이 필요할 수 있습니다.

Studio Monmal은 일정·작업·연락처·계정 정보·토큰을 수집하는 개발자 서버를 운영하지 않습니다. 이 데이터는 광고, 행동 추적, 판매, 신용도/대출 판단, AI 학습을 위해 사용하거나 제3자에게 제공하지 않습니다. Chrome·운영체제가 알림 내용을 표시하고, 사용자가 음성을 켠 경우 기기에 설치된 로컬 음성으로 제목을 읽을 수 있습니다. 앱은 원격 음성을 선택하지 않습니다. Google에서 열기나 문서 링크를 직접 선택하면 해당 외부 사이트가 열리며 그 사이트의 정책이 적용됩니다.

4. 로컬 저장·보존·진단

계정 식별자와 이메일, 승인한 범위, 캘린더/일정/작업 캐시, 설정, 초안, 알림·확인·다시 알림 기록은 해당 Chrome 프로필의 chrome.storage.local에 보관합니다. 방문한 달의 일정을 빠르게 표시하려고 여러 조회 기간의 캐시를 유지하며, 저장량이 커져도 캐시와 알림 쓰기가 실패하지 않도록 unlimitedStorage를 사용합니다. 현재 버전은 OAuth 액세스/갱신 토큰을 자체 저장소나 백업 파일에 기록하지 않고 실행 메모리에서 요청에 사용합니다. Chrome 자체의 인증 캐시는 별도로 관리됩니다.

중복 알림을 막는 수신 기록은 90일을 넘긴 항목을 정리합니다. 설정·초안·조회 캐시·일부 확인 기록은 계정 정리 또는 확장 제거 전까지 남을 수 있습니다. 앱은 현재 알림 창의 생성·종료·버전 갱신 시각, 숫자 창 식별자와 개수 등 진단 메타데이터를 최근 128개까지 기기에 기록합니다. 이 진단에는 일정 제목·계정·URL·토큰을 넣지 않으며 서버로 전송하지 않습니다.

설정 내보내기는 환경설정과 캘린더별 기본 알림을 JSON 파일로 저장합니다. 설정 키에 계정/캘린더 식별자가 포함될 수 있지만 일정 본문, 연락처 캐시와 로그인 토큰은 포함하지 않습니다. 로컬 데이터와 내보낸 파일에 별도의 앱 자체 파일 암호화를 제공하지 않으며 Chrome 프로필·운영체제의 접근 통제에 의존합니다. 내보낸 사본은 사용자가 보관·삭제합니다.

5. 알림 선택권·연결 해제·삭제

설정에서 일정 알림을 끄거나 방해 금지를 사용할 수 있습니다. 앱 알림 창을 X로 닫으면 기본적으로 미확인 알림을 5분 뒤 다시 표시합니다. ‘창을 닫은 미확인 알림을 5분 후 다시 표시’를 끄면 이 자동 재표시를 중단하며, 새 일정 알림과 직접 지정한 다시 알림은 유지됩니다. 확인은 해당 알림을 처리하고 다시 알림은 선택한 시각까지 보류합니다. 시스템 알림의 X는 해당 알림 확인 처리입니다.

앱에서 계정 연결을 해제하면 해당 로컬 계정과 조회 캐시, 대기/연기 알림을 정리합니다. 계정 식별자가 포함된 일부 설정·초안·처리 기록은 남을 수 있습니다. Google 서버의 권한은 Google 계정의 서드 파티 연결에서 철회하세요. 확장을 사용 중지하면 실행을 멈추며, 제거하면 그 Chrome 프로필의 확장 저장 데이터를 삭제합니다. Google 원본 일정과 이미 저장한 변경은 Google에서 관리하며, 내보낸 파일과 운영체제 알림은 별도로 삭제합니다.

1. Scope and operator

This policy applies to SyncBox Calendar, a Chrome extension managed by Studio Monmal. It displays calendars and events for Google accounts you connect, manages events, provides reminders and snoozing, and offers optional Tasks and contact features. Data is processed on your device and through Google services. No separate Studio Monmal account or calendar-processing server is used.

2. Data and purposes

  • Account and authentication. Google account identifiers, email addresses, and granted scopes identify accounts and separate requests. OAuth tokens provided by Chrome Identity authorize Google API requests. You do not enter your Google password into the extension.
  • Calendars and events. The extension reads calendar identifiers, names, colors, time zones, access roles, defaults, and event titles, dates, times, locations, descriptions, attendees, recurrence, visibility, reminders, and change identifiers. This supports the calendar, search, event summaries/editing, badges, notifications, and synchronization. Your save and delete actions update Google Calendar. If you select attendee change emails, Google may deliver updates to attendees.
  • Optional tasks and contacts. With an additional Google grant, the extension reads task lists, titles, notes, due dates, and completion state and applies changes you request. Optional contact access reads names and email addresses for attendee search and completion.
  • Input and preferences. Text you explicitly submit through the selection menu or omnibox becomes an event draft. The extension does not automatically collect general browsing history or page content or inject code into web pages. It processes themes, views, notification preferences, snooze times, and settings files you select.

3. Google connections and third parties

Account verification and Calendar requests go directly over HTTPS to www.googleapis.com, Tasks to tasks.googleapis.com, and contact search to people.googleapis.com. Chrome Identity and Google manage sign-in, authorization, and Chrome's token cache. Basic Google grants cover calendar reads, event management, and email verification. Calendar-list changes, Tasks, and contact reads may request additional approval when used.

Studio Monmal operates no developer server collecting extension calendars, events, tasks, contacts, account data, or tokens. This data is not used or shared for advertising, behavioral tracking, data sales, credit/lending decisions, or AI training. Chrome and your operating system may display notification contents. Optional speech uses a locally installed voice to read titles; remote voices are not selected. Choosing Open in Google or a documentation link opens the destination website under its own policy.

4. Local storage, retention, and diagnostics

Account identifiers/emails, granted scopes, calendar/event/task caches, preferences, drafts, pending notifications, acknowledgements, and snoozes are stored in chrome.storage.local for that Chrome profile. Cached periods are retained for fast navigation. unlimitedStorage prevents growing caches and shared reminder writes from failing at the normal quota. The current version uses OAuth tokens in execution memory and does not write access/refresh tokens into its own storage or settings exports. Chrome manages its own authentication cache separately.

Receipt records used to prevent duplicate alerts are pruned after 90 days. Preferences, drafts, queried caches, and some acknowledgement records may remain until account cleanup or extension removal. A local diagnostic log keeps at most 128 recent own reminder-window lifecycle/version records containing timestamps, numeric window IDs, and counts. It excludes event titles, accounts, URLs, and tokens and is not sent to a server.

Settings exports contain preferences and calendar-specific reminder defaults as JSON. Settings keys may include account/calendar identifiers. Event bodies, contact caches, and login tokens are excluded. Local storage and exported files do not have separate application-level file encryption; protection relies on Chrome-profile and operating-system access controls. You manage exported copies.

5. Notification choices, disconnection, and deletion

Turn event notifications off or use quiet hours in settings. Closing the app alert window with X repeats outstanding alerts after five minutes by default. Turning off the five-minute repeat option stops this automatic reopening; new event alerts and snoozes you explicitly select continue to work. Acknowledgement handles an outstanding alert, and snoozing defers it until your selected time. Closing an operating-system notification acknowledges that notification.

Disconnecting an account removes that local connection, queried caches, and pending/snoozed alerts. Some identifier-bearing preferences, drafts, and processing records may remain. Revoke server-side Google permissions through third-party connections in your Google Account. Disabling stops the extension. Uninstalling removes extension storage for that Chrome profile. Manage original events and changes already saved in Google separately, and delete exported files and operating-system notifications separately.

6. Google data and Limited Use

Information received from Google APIs is used for the calendar, event, task, attendee-entry, and reminder features disclosed here. Its use and transfer comply with the Limited Use requirements of the Google API Services User Data Policy and the Chrome Web Store User Data Policy.

7. Chrome permission purposes

  • identity: Google authorization and tokens. storage and unlimitedStorage: local accounts, caches, preferences, drafts, and reminder state.
  • alarms: default one-minute synchronization and upcoming alert/snooze deadlines. Chrome, sleep, and network conditions can delay actual execution.
  • notifications: selected system notifications. offscreen: packaged local sounds. tts: optional local speech.
  • contextMenus: event drafts from explicitly selected text. sidePanel: calendar display in Chrome's side panel. Google host permissions support only the account, Calendar, Tasks, and People requests described above.
